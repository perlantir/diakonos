# Diakonos v1.7 Part A — checkpoint

**Branch:** `phase/7-v1.7` (cut from `phase/6-v1.6`)
**Status:** Implemented. Trigger safety + CWD plumbing empirically
verified. End-to-end routing through claude.ai still blocked on Nick

**Timestamp:** 2026-05-14T17:38:53Z

## What landed

1. **PaneMode** model + persistence v3 with v2/v1 migration. Default
   `.soloChat` for chat panes (silent behavior change vs v1.5/v1.6;
   migration banner is a Part B item). Header chip toggles
   `.soloChat` ↔ `.coordinator`.
2. **Role cards** on disk under `~/Library/Application Support/Diakonos/RoleCards/`.
   5 bundled defaults (~200 words each) auto-seeded on first run.
   Settings tab "Role Cards" with TextEditor + auto-bumping-patch save.
3. **5-layer context composer**: Protocol → Pane Mode card → User Prefs
   → Project (AGENTS.md+context.md+CLAUDE.md) → Session.
4. **AGENTSReader**: reads + templates the canonical project docs.
   Hashes (SHA-256) the concatenated body so the envelope can echo a
   short `context_hash`.
5. **Trigger safety hardening**, five rules:
   - DOM attribution (user-only selector — verified, see below)
   - Message-start only
   - Not in quotes / code blocks
   - `\Code:` escape
   - First-route NSAlert with Confirm / Cancel / Always (per-conversation)
6. **9-state RouteStateMachine** with onTransition → SessionEventLog.
7. **RouteEnvelope** (YAML frontmatter + reply contract) prepended to
   subprocess stdin.
8. **CWD fix.** `Process.runWithCWD(cwd:)` sets
   `currentDirectoryURL` before `.run()`. Startup self-test
   (`CWDSelfTest.run`) on every app launch logs PASS/FAIL to NSLog.
9. **Per-route snapshots** (role-card version + protocol version +
   project context hash + createdAt) frozen at session start.
10. **Append-only JSONL event log** at
    `~/Library/Application Support/Diakonos/Sessions/<conv-id>.jsonl`.
11. **Refactored ChatBridge** — thin polling shell on top of
    TriggerDetector + RouteStateMachine + RouteDispatcher.
12. **Browser MCP guardrail** — every `browser_*` tool description now
    carries an explicit UNTRUSTED-CONTENT warning. Route detection
    structurally cannot fire on browser content (only chat-kind
    sandboxes register with ChatBridge).

## Empirical verification

### Trigger safety: DOM attribution (Coordinator AI emits "Code:" does NOT route)

Synthetic DOM probe run 2026-05-14 against the live container
Chromium:

```
[user count] 5
[asst count] 2
[last user text] \\Code: escaped should not fire
[last user id] m7
[asst contains Code:] True
[claude user-message] 1
```

The synthetic DOM included an assistant message containing
"Code: this is a tip" plus user messages with various trigger
patterns. The `[data-message-author-role="user"]` selector matches
ONLY the user-authored nodes; the assistant's "Code:" emission is
**invisible** to the selector. The "Coordinator AI emits Code: does
NOT route" guarantee is structural, not heuristic.

### Trigger safety: string-level rules

Standalone Swift test mirroring `TriggerDetector.classify` — 11/11 PASS:

```
[PASS] plain Code: routes
[PASS] plain Codex: routes
[PASS] Exit: closes
[PASS] backslash escape \Code: does NOT fire
[PASS] fenced ```Code: ``` does NOT fire
[PASS] block-quoted > Code: does NOT fire
[PASS] Code: NOT at message start does NOT fire
[PASS] leading whitespace: trimmed and fires
[PASS] plain message with active thread → continuation
[PASS] plain message with no thread → no fire
[PASS] Case-sensitivity: code: (lowercase) does NOT fire
=== 11 pass / 0 fail ===
```

### CWD fix (route Code: pwd → response shows project folder)

Independent of routing — empirical proof of the underlying
`Process.currentDirectoryURL` plumbing:

```
[PASS] cwd=/tmp /bin/pwd -L → /private/tmp
[PASS] cwd=/usr/local /bin/pwd -L → /usr/local
[PASS] cwd=/Users/perlantir/Projects/diakonos /bin/pwd -L → /Users/perlantir/projects/diakonos
=== 3 pass / 0 fail ===
```

The `/private/tmp` and lowercase-`projects` results are macOS canonical
path normalization (symlink resolution + case-insensitive APFS). The
subprocess CWD is set correctly. `CWDSelfTest.run` runs this check at
every app launch.

**End-to-end `Code: pwd` against a logged-in claude.ai chat** — still
blocked on Nick logging in. The v1.7 pipeline routes a real `Code: pwd`
through:
- TriggerDetector (verified)
- envelope composition (verified by inspection — UUID/hash/version present)
- `Process.runWithCWD(executable: "<claude bin>", arguments: ["--print", ...], cwd: projectRoot)` (CWD plumbing verified by self-test)
- claude --print reply parse (unchanged from v1.5)
- DOM postback (unchanged from v1.5)

So the pieces that are testable from outside a live claude.ai session
are individually verified. The remaining "the whole thing works"
