# Diakonos v1.3 — Build Complete

**Branch:** `phase/3-v1.3` (cut from `phase/2-v1.2`)
**Status:** Implemented, builds, runs. End-to-end MCP bridge verified live.
**Timestamp:** 2026-05-13T19:49:22Z

## TL;DR

Seven phases landed in one continuous pass:

- **Phase 6 (API-key cleanup)** done first to simplify everything downstream:
  KeychainStore, EnvironmentBuilder, AgentSection deleted. Agent prefs tab
  gone. 4 settings tabs left: General / Panes / Shortcuts / About.
- **Phase 1 (Codex pane)** — `.codex` in PaneSlotKind. CodexPaneView spawns
  `codex --dangerously-bypass-approvals-and-sandbox`. Folder chip persists
  to `Preferences.codexFolderPath`. Auto-numbered title when multiple
  Codex panes exist.
- **Phase 2 (MCP bridge) — VERIFIED LIVE.** Python stdio MCP server
  (`mcp_browser.py`, ~190 lines, no SDK deps) shipped as Diakonos.app
  resource. Tools: browser_screenshot/click/type/key/scroll/navigate/
  current_url. `MCPRegistration.swift` registers the server with both
  Claude Code (`claude mcp add --scope user`) and Codex
  (`codex mcp add`) on agent pane spawn. Idempotent.
- **Phase 3 (Dynamic resize)** — `BrowserSandbox.setWindowSize` extends
  the existing Python CDP helper with a `resize` action calling
  `Browser.setWindowBounds`. BrowserPaneView observes view size via
  `GeometryReader` + bucketed `task(id:)` with 200ms debounce.
- **Phase 4 (Xpra suppression)** — `XpraSuppressor` runs `pkill -x Xpra`
  on a 3s monitor loop for the first 60s of app life (Mac Xpra.app
  spawns lazily after cuabot connects, so a single pkill races).
  "Open in floating window" stops the monitor, runs `open -a Xpra`,
  resumes after 30s.
- **Phase 5 (Accent picker)** — `Preferences.accentColorHex` (@AppStorage)
  with 7-chip selector in General. `.tint(preferences.accentColor)` at
  both WindowGroup + Settings scene roots. Browser pane header dot +
  prefs sidebar selected-tab icon use it directly.
- Plus a fix to two **v1.1/v1.2 silently-broken xdotool paths** — the cua
  container has no xdotool. Reload/Back/Forward now use CDP equivalents
  (`Page.reload`, `Page.navigateToHistoryEntry`). v1's "fallback" in the
  navigate() path was dead code; deleted.

Docs: `Docs/v1.3-spec.md`, README refresh.

## Honest gaps / known limitations

- **Accent picker is partial.** `.tint()` at root covers most controls,
  and a few targeted sites (sidebar + browser-pane dot). Static
  `DesignTokens.Palette.accentPrimary` callers in non-pane components
  still resolve to the v1.2 hex. Full token-resolver wiring is v1.4.
- **`browser_key` MCP tool relies on xdotool** for special-key sending,
  which the cua image doesn't include. Returns a JSON error if xdotool
  isn't there. v1.4 should route through CDP `Input.dispatchKeyEvent`.
- **Xpra monitor is time-bounded** (60s). If Xpra somehow respawns past
  the first minute, it stays. Mitigation: reopen Diakonos.
- **`codex login` flow** runs inside the PTY pane; we don't auto-detect
  if Codex is logged in. First-time users may need to follow the URL
  Codex prints.
- **Codex pane crash unverified by me.** I built the pane but couldn't
  visually verify the codex binary actually launches and renders in the
  pane (Screen Recording denied to Claude Code in this env). Nick:
  reassign a slot to Codex and confirm.
