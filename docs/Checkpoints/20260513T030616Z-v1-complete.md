## How Diakonos v1 hangs together

```
DiakonosApp (WindowGroup + Settings scene)
├── RootView
│   ├── WorkspaceToolbar  (dropdown, status indicator, agent toggle, settings, fullscreen)
│   └── WorkspaceView     (2x2 grid + draggable dividers)
│       ├── TerminalPaneView      → SwiftTerm + docker exec -it cuabot-xpra /bin/bash
│       ├── ClaudeCodePaneView    → SwiftTerm + docker exec -it cuabot-xpra /home/user/.local/bin/claude
│       ├── HermesAgentPaneView   → SwiftTerm + docker exec -it cuabot-xpra /bin/bash --login (orange themed)
│       └── BrowserPaneView       → WKWebView + URL bar
└── PreferencesWindow (NavigationSplitView with 6 tabs)
    ├── GeneralSection (appearance, accent, startup)
    ├── SandboxSection (status, CPU/memory, auto-update)
    ├── PanesSection   (layout summary, browser home)
    ├── AgentSection   (model, temperature, Keychain-backed API keys)
    ├── ShortcutsSection (read-only)
    └── AboutSection   (icon, version, credits)
```

**Sandbox lifecycle:** `CUASandboxManager` (`@MainActor ObservableObject`) starts on `RootView.onAppear`. Probes `GET http://localhost:7842/status` — if a server's already up, adopts it; otherwise spawns `npx cuabot --serve 7842` via `CUAProcessSupervisor`. Polls every 1.5s until `"ready":true`, then every 5s to keep the toolbar indicator honest.

**PTY pattern:** SwiftTerm's `LocalProcessTerminalView` natively allocates a Mac PTY when running `docker exec -it <container> …`. `-i` proxies stdin, `-t` allocates a tty inside the container, and Docker's native multiplexing handles the rest. No Python helper, no socket bridge — verified live (process tree shows three concurrent `docker exec` children under the Diakonos PID).

## Known issues / explicitly v0.2+

- **`hermes` is not in cua's Docker image.** Hermes pane runs themed bash as a v1 stand-in. v0.2 should `docker cp` a host-installed hermes into the container at sandbox-init, or detect host-side hermes and shell into it directly.
- **CPU/Memory sliders in Sandbox prefs** persist but don't apply (Docker daemon owns container resource limits).
- **`preferredModel` in Agent prefs** doesn't propagate to the Claude Code pane yet.
- **No "Reset sandbox" UI surface** — if cuabot crashes, the user has to quit and relaunch. Screen 06 covers v0.2's reset UX.
- **Browser pane is WKWebView, not sandboxed Chromium video stream.** Locked decision (D6). Upgrade in v0.3.
- **App icon is a programmatic facsimile**, not the designer's source from screen 09. Swap before public release.
- **Visual verification is by Nick** — Claude Code couldn't take screenshots in this environment.
