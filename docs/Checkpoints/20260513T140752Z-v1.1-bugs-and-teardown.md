# v1.1 — Bugs + service teardown

**Branch:** `phase/1-v1.1` (cut from `phase/0-v1-build`)
**Timestamp:** 2026-05-13T14:07:52Z

## Bug fixes

### Settings crash (Cmd+, / gear button)

**Root cause:** `Diakonos/UI/Preferences/SandboxSection.swift` line 5 declared
`@EnvironmentObject var sandbox: CUASandboxManager`, but the `Settings { }` scene
in `DiakonosApp.swift` only injected `Preferences`, never `CUASandboxManager`. The
first body evaluation crashed with "No EnvironmentObject of type CUASandboxManager
found." This shipped in v1; we never caught it because Claude Code's verification
in v1 didn't open prefs (no AppleEvents / Screen Recording).

**Fix:** Deleted `SandboxSection.swift` entirely (the v1.1 architecture pivot
removes the global sandbox from non-Browser surfaces anyway). Updated
`PreferencesWindow.swift` to drop the `case .sandbox` enum case and switch arm.
Settings now opens cleanly with five tabs (General, Panes, Agent, Shortcuts, About).

### Terminal keystroke bleed across panes

**Root cause:** `Diakonos/UI/Workspace/Panes/TerminalPaneView.updateNSView`
checked `if context.coordinator.lastSpawnKey != key` to gate respawning, but
`lastSpawnKey` was never assigned to `key` after `spawn`. Default `""`, so every
SwiftUI rerender called `term.terminate()` + restart on every pane. Constant
terminate/respawn churn racing across all three terminal panes scrambled
first-responder assignment.

**Fix:** Two changes in `TerminalPaneView.swift`:
1. Made `LocalProcessTerminalView` the representable's NSView directly (dropped
   the outer `NSView` wrapper). SwiftTerm's own `acceptsFirstResponder` now
   gates focus cleanly per pane.
2. Set `coordinator.lastSpawnKey = spawnKey()` at the end of `spawn(...)`, so
   `updateNSView` only respawns when configuration actually changes (which now
   happens only when Claude's project folder changes — by design).

## Service teardown

Deleted (no longer needed — all v1 panes used these to talk to the sandbox; v1.1
makes three of four panes native):
- `Diakonos/Services/CUASandboxManager.swift`
- `Diakonos/Services/CUAProcessSupervisor.swift`
- `Diakonos/Models/AgentMode.swift` (toolbar toggle removed per Nick's instruction)
- `Diakonos/UI/Workspace/Panes/SandboxedPaneBody.swift`
- `Diakonos/UI/Workspace/Panes/HermesAgentPaneView.swift`
- `Diakonos/UI/Preferences/SandboxSection.swift`

Kept (Browser pane will resurrect a minimal version):
- `Diakonos/Services/CUAHTTPClient.swift` — typed wrapper still used by the new `BrowserSandbox`.

Refactored:
- `Diakonos/UI/Toolbar/WorkspaceToolbar.swift` — removed `agentMode`, `sandboxState`,
  `StatusIndicator`, `SegmentedToggle`. Toolbar is now just: dropdown · spacer ·
  settings · fullscreen.
- `Diakonos/UI/RootView.swift` — removed `@StateObject sandbox` and the
  `agentMode` state. Reads `Preferences` from the env-object now.
- `Diakonos/Models/PaneKind.swift` — `.hermesAgent` → `.terminal2`; both
  terminals share the green accent + `terminal.fill` SF Symbol.
- `Diakonos/UI/Preferences/PreferencesWindow.swift` — dropped Sandbox tab.
- `Diakonos/Services/Preferences.swift` — dropped `autoStartSandbox`,
  `autoUpdateSandbox`, `sandboxCPULimit`, `sandboxMemoryGB`, `agentDefaultMode*`,
  `paneAssignmentsRaw`, `hermesKey`. Added `claudeCodeFolderPath` + computed
  `claudeCodeResolvedCwd` ($HOME if empty).
- `Diakonos/Services/KeychainStore.swift` — dropped `.hermes` case.
- `Diakonos/UI/Preferences/AgentSection.swift` — dropped Hermes key row.
- `Diakonos/UI/Preferences/GeneralSection.swift` — dropped Startup section
  (auto-start-sandbox + agent default mode both went away).
- `Diakonos/UI/Preferences/PanesSection.swift` — updated labels to reflect
  native-three + sandboxed-browser-one architecture.
- `Diakonos/UI/Preferences/ShortcutsSection.swift` — "Focus Hermes pane" →
  "Focus Terminal 2 pane"; "Reset sandbox" removed (no longer applicable).

Build succeeded on first attempt after these deletions/refactors.
