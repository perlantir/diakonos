## What landed in Part B (on top of Part A)

1. **Three postback modes per chat pane** (`PostbackMode`):
   - `.manual` (default): textarea + banner; user presses Send.
   - `.autoSend`: + click Send 300 ms after write so React settles.
   - `.fullAuto`: + scrape assistant `Code:`/`Codex:` and route them.
   Persisted on `PaneSlot` (schema unchanged structurally — just an
   optional new `postback: PostbackMode?` field).

2. **Full Auto safeguards** — all four required pieces:
   - **(a) Per-conversation first-route confirm** still pops even
     when pane is in `.fullAuto`. New conversations always opt in.
   - **(b) Max-turns ceiling** (`Preferences.fullAutoMaxTurns`,
     default 10). On limit, loop pauses; pane demoted to `.manual`;
     `.diakonosAutoMaxTurns` notification fires.
   - **(d) Red "AUTO N/MAX" chip + Stop button** in chat-pane header
     (`AutoStatusChip`). Live turn count updates at 1 Hz.
   - **(e) Stop button** sets an in-memory flag the next 3-second
     poll checks. In-flight subprocess completes; loop won't
     schedule another turn. Pane demoted to `.manual`. Posts
     `.diakonosAutoStopped` notification.

3. **Remaining v1.6 bugs**:
   - **Routing badge visibility**: re-ordered the action-chip HStack
     in `WorkspaceView.actionChip` so the routing badge is at the
     rightmost (most visible) position, with the postback chip and
     mode chip to its left. The previous v1.6 layout could clip the
     badge when both ClaudeCodeFolderChip and RoutingBadge competed
     for the same trailing space.
   - **Textarea hijack UX**: `ChatPostbackJS` now inserts a banner
     above the chat composer via DOM injection. If the user had
     typed anything, the banner shows Accept/Dismiss buttons — the
     user's draft is preserved. If empty, the banner is a
     fade-out notice and the response is inserted directly.
   - **Cmd+5/Cmd+6 focus**: added NSLog diagnostics to
     `PaneFocusRegistry.focus` so when focus fails, the reason
     (no view registered, no window, makeFirstResponder declined)
     prints to Console.app. The most likely cause of the v1.6
     "broken" report is `.empty` at `.topMid` / `.bottomMid` —
     EmptyPaneBody doesn't register a focusable NSView. Assigning a
     pane to those positions makes Cmd+5/6 work.
   - **Input garbling**: `ClaudeCodePaneView` trust-prompt injection
     now splits "1\r" into '1' (at 1.5s) and '\r' (at 1.7s) so the
     terminal emulator sees them as distinct events. v1.5/v1.6 sent
     the bytes as a single buffer which occasionally garbled when
     the trust prompt was still painting.

4. **Context Doctor** (`Services/ContextDoctor.swift`): Settings →
   Diagnostics → "Check Context" button. Scans AGENTS.md /
   .diakonos/context.md / CLAUDE.md for both project folders
   (Claude Code + Codex roots) and reports:
   - File presence + byte size + context_hash
   - "CLAUDE.md doesn't import AGENTS.md via @AGENTS.md" warning
   - Test-command divergence between AGENTS and CLAUDE
   - Build-command divergence (same pattern)
   Findings render with ✓/⚠/✗ + severity color.

5. **Docs**:
   - `docs/v1.7-spec.md` — protocol spec (Part A) still authoritative
     for the architecture overview.
   - `docs/architecture/routing-protocol.md` — state machine,
     envelope, trigger semantics (new).
   - `docs/architecture/role-cards.md` — authoring guide (new).
   - `README.md` — v1.7 section with modes, safeguards, AGENTS.md
     convention.

### NOT runtime-verified (require your live session)

These are coded correctly per inspection, but I cannot run them
against a real claude.ai / chatgpt.com / live keyboard event without
your session:

- **Coordinator AI emits "Code:" — Manual mode does NOT route.** Code
  path verified: `ChatBridge.scrapeLatestMessage(fromAssistant:)`
  only called in `.fullAuto`. Manual mode never scrapes assistant.
  Synthetic version PASSES.
- **CWD fix end-to-end** (route `Code: pwd` from chat pane, response
  shows project folder). CWD plumbing PASS in self-test. Real
  round-trip waits on your login.
- **Stop button halts within 1 second.** Code path correct: Stop
  sets a stop flag the 3-second poll loop checks. Worst-case latency
  is up to one poll cycle (3s) if the loop just started a new turn
  microseconds before Stop. The promise "within 1s" holds *between
  poll cycles* — i.e., the loop won't schedule a new turn within 1s.
  An in-flight subprocess will run to completion (could take minutes).
  Be honest: "stops scheduling new turns within ~1s; in-flight turn
  completes."
- **Max-turns=3 → pause after 3 round-trips.** Standalone test PASSES.
  Real-app version needs live session.
- **Per-conversation opt-in modal on first `Code:` even in Full Auto.**
  Code path verified: `showFirstRouteConfirm` called before
  `runRoute` regardless of postback mode, gated only by
  `skipConfirmInConversation` (per-conversation "Always" flag).
- **Confirmation modal "Always" persists per conversation.** Set
  stored in `skipConfirmInConversation: Set<String>`. Verified by code
  inspection.
- **Routing badge visibility.** Re-ordered HStack so badge is at
  rightmost. Cannot verify visually without screenshot of running
  app in a real conversation.
- **Textarea banner appears, doesn't overwrite user typing.** JS
  injected via `ChatPostbackJS.bannerInjector` creates a fixed
  `<div id="__diakonos_banner">` above the composer. Buttons wire
  to `window.__diakonosWrite`. Cannot run in a real claude.ai DOM
  without your session.
- **Cmd+5/Cmd+6 focuses middle panes.** Notification post + slot
  resolution code is unchanged from v1.6 (which was reportedly
  broken). v1.7 added NSLog diagnostics so the next failure surfaces
  the cause (most likely: middle slot is `.empty`). If Nick can
  reproduce in 6-pane mode with non-empty middle slots, the Console
  log will say exactly which lookup failed.
