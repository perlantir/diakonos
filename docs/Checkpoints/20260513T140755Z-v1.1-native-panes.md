# v1.1 — Native pane rewrites (Terminal / Terminal 2 / Claude Code)

**Branch:** `phase/1-v1.1`
**Timestamp:** 2026-05-13T14:07:55Z

## What landed

### TerminalPaneView (rewrite)
- Generic now — used by both TL Terminal and BL Terminal 2.
- Spawns `$SHELL -l` in `$HOME` (or whatever `workingDirectory` override is passed).
- Drops the docker-exec indirection. Real PTY, real `$PATH`, real filesystem.
- Fixes the keystroke-bleed bug (see other checkpoint): `LocalProcessTerminalView`
  is now the representable's NSView directly; no outer wrapper; `lastSpawnKey`
  is set after spawn so we don't respawn on every SwiftUI rerender.
- Optional `commandOverride: TerminalCommand?` param for panes that want to run
  something other than a shell (used by Claude Code).
- Optional `spawnIdentity: String` param so view consumers can declare "if this
  changes, respawn the process" (Claude Code uses this on folder change).

### TerminalCommand (new type)
- Small struct `{ executable, args, execName }` for the override pattern. Lives
  at the bottom of `TerminalPaneView.swift`.

### ClaudeCodePaneView (rewrite)
- Wraps `TerminalPaneView` with a `commandOverride`:
  `$SHELL -l -c "cd \"<folder>\" && exec claude --dangerously-skip-permissions"`.
  `exec` so the shell hands the PTY directly to claude (no extra hop in the
  process tree; verified at runtime — `claude` shows under Diakonos's PID with
  no zsh parent because of `exec`).
- `spawnIdentity: "claude:<folder>"` so any folder change triggers respawn.
- Defaults to `$HOME` when no folder has been picked (matches Step 2 §b.3).

### ClaudeCodeFolderChip (new)
- Header chip mounted in the pane header via `PaneHeader.actionChip` slot.
- Shows the folder's last path component (e.g. `diakonos` from
  `/Users/perlantir/Projects/diakonos`) in a small bordered pill.
- Click → `NSOpenPanel` for directory selection. On confirm, writes the path
  to `preferences.claudeCodeFolderPath`, which is `@AppStorage`-backed so it
  persists across launches. The TerminalPaneView's `spawnIdentity` changes,
  triggering kill + respawn with the new cwd.

### PaneView / PaneHeader (generic)
- `PaneView<Body, ActionChip>` now takes an `actionChip` ViewBuilder slot.
- Old call sites (panes without chips) still work via an `ActionChip == EmptyView`
  convenience initializer.

### WorkspaceView (refactor)
- No more `@EnvironmentObject CUASandboxManager`. Reads `Preferences` from env.
- `paneCell(_:w:h:)` switches on `PaneKind`:
  - `.terminal` / `.terminal2` → `TerminalPaneView()` (defaults to `$SHELL` in `$HOME`)
  - `.claudeCode` → `ClaudeCodePaneView(preferences: preferences)` with the
    folder-chip action chip
  - `.browser` → `BrowserPaneView()` (its own state via internal `BrowserSandbox`)
- All four pane states report `.running` to the pane header — there's no
  global gating anymore. Browser pane's own sandbox state surfaces as a dot
  on its URL bar.

## Verified at runtime

Process tree under a running Diakonos.app:
```
56134  Diakonos
├── 56151  /bin/zsh -l                              # Terminal pane
├── 56152  claude --dangerously-skip-permissions    # Claude Code pane (exec'd from zsh)
└── 56160  /bin/zsh -l                              # Terminal 2 pane
```

That's three native PTYs on the host, no docker hops. Confirmed by `ps` —
listed in this checkpoint above. App stable at 160 MB RSS, 1.3% CPU at idle.
