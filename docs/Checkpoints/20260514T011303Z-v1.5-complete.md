## Headlines

### 1. Browser sizing — actually fixed this time

**v1.4's diagnosis was wrong:** xrandr + setWindowBounds shrunk the
display + chromium, but cuabot's `/screenshot` returns a fixed 1280×720
regardless, so the small chromium became 25% of the screenshot with
black margin.

**v1.5 fix:** chromium launches with `--start-fullscreen --start-maximized`,
followed by `wmctrl -r 'Chromium' -b add,fullscreen`. The display stays
at 2560×1440; chromium fills it; the screenshot is 100% chromium.

**Verified live in this session:**
```
$ open Diakonos.app
$ curl -s -X POST http://localhost:7842/screenshot ... > /tmp/v15_shot.png
```
The shot shows Google.com filling the entire frame. (Before v1.5,
chromium was a small box in the top-left.)

### 2. Two new sandboxed pane kinds — `.claudeChat`, `.chatgptChat`

- Non-headless chromium per pane (headless triggers Cloudflare on
  claude.ai — verified live).
- Own `--user-data-dir` per pane for login persistence.
- Own CDP port (9223 / 9224).
- Off-screen at (4000, 4000) so they don't visually overlap Browser pane.
- Captured via CDP `Page.captureScreenshot` (works regardless of focus).

Audit pass: every switch over `PaneSlotKind` (7 cases) updated to
handle `.claudeChat` and `.chatgptChat`.

### 3. ChatBridge — bidirectional routing

- Per-chat-pane CDP polling every 3 s (`Runtime.evaluate` on the
  user-message selectors).
- Triggers `Code:` / `Codex:` / `Exit:` at message start (case-sensitive,
  message-start only per spec §b.4).
- Per-conversation thread state keyed by URL (`/chat/<uuid>` for
  claude.ai, `/c/<uuid>` for chatgpt.com).
- Agent invocation **with session-id continuity** (per Nick's push-back
  against one-shot):
  - Claude Code: `claude --print --output-format json` → captures
    `session_id` → subsequent turns use `--resume <id>`.
  - Codex: `codex exec --json` → best-effort `session_id` extract →
    `codex exec resume <id>` for follow-ups.
- **Post-back: textarea-only, NO auto-submit** (per Nick's §b.1 push-back).
  React-aware DOM injection via `execCommand('insertText', …)` or the
  native `HTMLTextAreaElement` value setter. User reviews + presses Send.

### 4. Diagnostics tab

Last 500 ChatBridge events in-memory. Categories: trigger / route /
response / postback / selector / error / info. Selector-failure events
surface loudly so users know when DOM has shifted.

### 5. Visual badge — `→ Claude Code` chip

`RoutingBadge` in chat pane header when a thread is active. Color
matches the target agent's accent (Claude purple, Codex green).

## v1.5 architectural changes

- **Two enums** continue to coexist by design: `PaneSlotKind` (UI model,
  user-controlled). `PaneKind` was removed in v1.4 cleanup.
- **`BrowserSandbox`** owns the foreground Chromium on `:100` for the
  Browser pane.
- **`ChatPaneSandbox`** (new) per `.claudeChat` / `.chatgptChat` slot,
  owns off-screen Chromium + CDP plumbing.
- **`CDPInput`** (new) — Swift wrapper around per-port CDP via cuabot
  `/bash` + inline Python `websockets` client.
- **`ChatBridge`** — `@MainActor` singleton, polls registered chat
  sandboxes, dispatches triggers, posts back.

## Honest gaps

- **Full agent round-trip not verifiable by Claude Code in this env.**
  Requires a logged-in claude.ai / chatgpt.com session. Nick logs in
  once (login persists via user-data-dir), then triggers can be tested
  with real chats. The internal components are exercised:
  - DOM scrape JS evaluated; non-null returns wire to ChatTriggerParser
  - Trigger parser handles all four cases (startThread, exit,
    continuation, plain)
  - Claude --print invocation tested in v1.4 verification (returns
    JSON with `session_id`)
  - Postback JS prepared but couldn't run against a real authenticated
    chat
- **DOM selectors WILL break.** When claude.ai or chatgpt.com redesigns,
  Diagnostics surfaces `selectorMissing`. Documented in v1.5 spec as
  the maintenance fragility.
- **Codex --json response extraction** is best-effort. Codex's event
  stream is less structured than claude's. Documented.
- **Off-screen positioning at (4000, 4000)** can theoretically be
  visible if the user has a very large display in the sandbox. v1.6
  could move to a more aggressive position.
- **Routing badge** finds the FIRST active routing across registered
  sandboxes (no slot→sandbox reverse map). Practical edge: only matters
  if user has BOTH claude.ai AND chatgpt.com routing simultaneously
  to different agents. Documented as a v1.6 polish.
