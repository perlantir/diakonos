## Decisions / non-blockers

- **App icon is a programmatic facsimile**, not the designer source from screen 09. It's a flat indigo gradient rounded square with a white hex-cube glyph. Visually adjacent to the designer's spec but not pixel-identical. Per Step 2 default; replace before public release.
- **Settings scene uses macOS 14 `Settings { }` syntax**, which auto-binds `Cmd+,`. The earlier toolbar settings button (in `WorkspaceToolbar`) still calls `Selector("showSettingsWindow:")` which now resolves correctly to this scene.
- **Sidebar styling:** uses the standard SwiftUI `.sidebar` list style with custom accent-tinted icon on selection. Doesn't pixel-match the design's bespoke sidebar but is HIG-correct for macOS 14.
- **Sandbox section's CPU/Memory sliders are advisory** — they're saved to `UserDefaults` but not piped into the Docker daemon (Docker resource limits are set in Docker Desktop, not by Diakonos). Fields are placeholders for v0.3 when we may shell into the docker CLI to apply per-container limits.
- **Shortcuts section is read-only.** Customization (per the design's component states) is v0.2.
- **Model list in Agent section** uses my actual model knowledge: Claude Opus 4.7, Sonnet 4.6, Haiku 4.5 (with the dated ID for Haiku per current API), plus GPT-4o and Gemini 2.0 Flash for the optional non-Anthropic stack. No fabricated model names.

## Issues

- **Hermes API key field** is stored in Keychain but unused — the v1 Hermes pane runs bash (since hermes binary isn't in cua's image). Field is present for v0.2's host-side hermes integration.
- **`preferredModel` choice doesn't propagate anywhere yet** — Claude Code in the Claude pane uses its own config; Diakonos doesn't (yet) override the model the pane requests. v0.2 should pass it via env var to `claude`.
- **CPU/Memory slider values do nothing** beyond persistence (see Decisions).

That's v1 prefs scope per the build spec. Ship.
