# Diakonos v1.2 — Polish pass

**Date:** 2026-05-13
**Branch:** `phase/2-v1.2` (cut from `phase/1-v1.1`)
**Status:** Implemented (not merged to main)

## Theme

v1.2 is the polish pass after v1.1's architecture pivot. Every Settings
control drives real behavior or is gone. The four pane positions become
re-assignable slots (still fixed in space, kinds swappable). Pane header
buttons are wired. Cmd+1..4 focus panes. The Browser pane is rebuilt
from scratch around **Option Z** — a 10 fps screenshot stream from cuabot
with mouse + keyboard forwarded through cuabot's HTTP API.

## What's new

### Re-assignable panes (v1.2 model)
- `Diakonos/Models/PaneSlot.swift` — a slot is a (position, kind, viewState)
  triple. Kinds: `.empty`, `.terminal`, `.claudeCode`, `.browser`.
- `Diakonos/Services/WorkspaceLayout.swift` — owns the four slots,
  persists them as JSON in UserDefaults under key
  `workspaceLayout.slots.v1`. Default: TL Terminal, TR Claude Code,
  BL Terminal, BR Browser (matches v1.1).
- Closing a pane (xmark button) sets the slot to `.empty` and renders
  `EmptyPaneBody` (per `design/screens/07-empty-pane.png`) with a
  dropdown to pick {Terminal, Claude Code, Browser}.
- Multiple Terminal slots get auto-numbered titles via
  `WorkspaceLayout.title(for:)` ("Terminal", "Terminal 2", "Terminal 3").

### Pane controls wired
- **3-dot menu** opens a context menu per pane kind:
  - Terminal: Reset shell.
  - Claude Code: Restart Claude Code, Change project folder…
  - Browser: Reload, Open in floating window, Reset sandbox.
- **Minimize** collapses the pane to its 36 pt header. Click again to
  restore. (`viewState: .minimized`; rendering hides the body.)
- **Maximize** flags `WorkspaceLayout.maximizedSlotID`; WorkspaceView
  renders only that slot full-bleed. Click again to restore the grid.
- **Close** tears down the slot's process and renders the empty
  placeholder.

### Cmd+1..4 focus
- `Diakonos/Services/PaneFocusRegistry.swift` — weak-ref map from
  `PaneSlotPosition` → focusable `NSView`. Pane views register on
  appear, deregister on disappear.
- `DiakonosApp.commands` provides a "Pane" menu with four entries,
  each with `keyboardShortcut("1".."4", modifiers: .command)`.
- Each menu item posts `Notification.Name.diakonosFocusSlot` with the
  position raw value; `WorkspaceView.onReceive(...)` calls
  `PaneFocusRegistry.focus(_:)` which sends `makeFirstResponder` to
  the registered view.

### Bug fixes (v1.1 → v1.2)

| Bug | Root cause | Fix |
|----|-----|----|
| Cmd+, / gear didn't open Settings | `NSApp.sendAction("showSettingsWindow:")` did not reliably route through the responder chain when focus was inside a SwiftTerm pane | Use `@Environment(\.openSettings)` from RootView, call `openSettings()` directly on gear tap |
| Folder chip click did nothing | `NSOpenPanel.runModal()` from inside a `Button` action ran on a non-key NSApp, panel could come up behind or not at all | `NSApp.activate(ignoringOtherApps: true)` first; then `panel.beginSheetModal(for: keyWindow)` (sheet) or runModal fallback |

### Claude Code auto-trust
- On every Claude pane spawn, after a 1500 ms delay, the pane injects
  `1\r` into the PTY via SwiftTerm's `process.send(data:)`.
- Constant `claudeAutoTrustEnabled = true` at the top of
  `ClaudeCodePaneView.swift` — flip to disable in one line if a future
  claude version's UX changes.

### Settings — every control wired or deleted
- **Theme:** drives `preferredColorScheme` via `Preferences.colorScheme`
  computed property. Verified.
- **Accent color:** v1.2 ships with `.tint(DesignTokens.Palette.accentPrimary)`
  applied at the App root and Settings scene. The static accent chip row
  in General is **display-only** — chips are visual previews, not a
  picker. Wiring full accent selection requires plumbing a runtime token
  resolver across the app, which is real v1.3 surgery. Documented gap.
- **Preferred model:** Picker is wired through `EnvironmentBuilder.aiEnv()`
  to inject `ANTHROPIC_MODEL=<chosen>` into the Claude Code pane (and any
  Terminal pane the user might run `claude` in).
- **API keys (Anthropic / OpenAI / Google AI):** Keychain reads injected
  as `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GOOGLE_API_KEY` env vars on
  pane spawn via `EnvironmentBuilder`. Persisted on `onSubmit`.
- **Browser homepage URL:** BrowserPaneView reads `preferences.browserHomeURL`
  on appear; first `navigate(to:)` uses it.
- **Deleted as unwired:** Agent → Temperature slider (had no consumer);
  Manual/Autonomous toggle (was decoration in v1.1; removed earlier).

### Browser pane — Option Z (the big one)

**Architecture:**
- `Diakonos/Services/SandboxStream.swift` — `@MainActor ObservableObject`
  polling `POST /screenshot` every ~100 ms (backs off to 500 ms on
  consecutive errors). Decodes the JSON payload
  `{ image: <base64 JPEG>, scale: <coord-scale> }` into an NSImage,
  publishes `latestImage`, `nativeSize`, and `coordScale`.
- `Diakonos/Services/SandboxStream.SandboxInput` — wraps cuabot's
  `/click`, `/move`, `/scroll`, `/type` HTTP endpoints. Performs the
  coord translation `local → native → cuabot input space (= native × scale)`
  using the latest `coordScale` from `SandboxStream`. Falls back to
  `xdotool key` over `/bash` for special keys because cuabot's
  `/key`/`/keydown`/`/keyup` are 404 in the live API despite being
  advertised in `--help` (verified live in Phase E discovery).
- `Diakonos/UI/Workspace/Panes/BrowserPaneView.swift` — vertical stack
  of URL bar + `SandboxScreenView` (an NSViewRepresentable). The
  `SandboxScreenNSView` is a pure AppKit view that paints the JPEG
  using aspect-fit, captures `mouseDown`/`rightMouseDown`/`scrollWheel`/
  `keyDown`, and forwards through `SandboxInput`. 1 px accent outline
  when first responder (per Step 2 §b.5).

**CDP integration (URL feedback + tab reuse):**
- `BrowserSandbox.ensureChromium()` launches chromium with
  `--remote-debugging-port=9222 --remote-debugging-address=127.0.0.1`
  inside the sandbox.
- `BrowserSandbox.fetchCurrentURL()` runs
  `curl -s http://localhost:9222/json` *inside the container* via
  `POST /bash`, parses the JSON array, returns the first `type == "page"`
  entry's `url`. Polled every 2 s by the URL bar's `task(id:)`.
- `BrowserSandbox.navigate(to:)` first calls `ensureNavHelper()`, which
  installs a tiny Python script at `/tmp/diakonos-nav.py` inside the
  container that uses `websockets` to send `Page.navigate` to the
  current page's CDP WebSocket URL. Then runs the helper via
  `POST /bash` with the URL. **This is how URLs reuse the current tab
  instead of opening new ones.** If the helper fails (no `websockets`
  module, no tabs), Diakonos falls back to xdotool `Ctrl+L → type URL →
  Return` against the visible Chromium window.

**Verified live in this session:**
- `POST /screenshot` round-trip: ~47–70 ms, 45–55 KB JPEG, native 1280×720,
  `scale=0.667` (input click coord space = 853×480).
- `/click` returns `scaledCoords:{x,y}` confirming Diakonos's coord
  translation matches cuabot's expectations.
- The Python CDP helper was installed by Diakonos at /tmp/diakonos-nav.py;
  invoking it from outside Diakonos navigated Chromium from google.com
  to duckduckgo.com via `Page.navigate` (CDP WebSocket). End-to-end
  confirmed.

**Floating window opt-in:**
- Browser 3-dot menu → "Open in floating window" → spawns a fresh
  chromium window (`chromium --new-window about:blank`) inside the
  sandbox. Xpra streams it to the cuabot-default surface; Diakonos does
  not embed it. v0.2 may polish this further.

### Toolbar

  (non-interactive) · spacer · settings · fullscreen.

## v1.3 punch list (deferred from v1.2)

- Full runtime-pickable accent color (currently the chip row is
  display-only; SwiftUI `.tint()` covers most controls).
- Drag-to-reorder pane positions (positions are fixed in v1.2).
- Per-Browser-pane state (right now one Browser pane drives one
  sandboxed Chromium; multiple browser slots would need named sessions).
- Persist a list of recent URLs in the Browser pane.
- "Clear" terminal action (needs a notification path into SwiftTerm's
  view; v1.2 ships with only "Reset shell").
