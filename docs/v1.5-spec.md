## 1. Browser sizing — the actual fix

### v1.4 was chasing the wrong target

**Diagnosis (this session, live):** cuabot's `POST /screenshot` returns a
**fixed 1280×720 JPEG** with `scale=0.667` regardless of the X display
resolution. v1.4 was shrinking the X display via `xrandr` and calling
`Browser.setWindowBounds`, both of which make chromium smaller — but the
screenshot stays 1280×720, so a smaller chromium just produces more black
margin. Result: ~25% Chromium fill. The visual proof was captured at
`/tmp/cua_shot.png` (v1.4 state) and `/tmp/cua_shot2.png` (after fullscreen).

### The fix

- **Drop xrandr mode-switching.** Display stays at 2560×1440.
- **Drop `Browser.setWindowBounds`.** Window sizing was unnecessary.
- **Launch chromium with `--start-fullscreen --start-maximized`.**
- **Re-assert** with `wmctrl -r 'Chromium' -b add,fullscreen` after launch
  (some WM hints take a moment) and on every `resize` action.

Result: chromium fills the entire X display (1920×1080 effective area on
this image). cuabot scales to 1280×720 for the screenshot. Diakonos's
Browser pane aspect-fits the 16:9 image into the pane — at the default
2×2 layout, this means ~100% fill, no black margins.

**Verification (this session):** `/tmp/cua_shot2.png` shows full Hacker
News content; `/tmp/v15_shot.png` after v1.5 build + relaunch shows
full Google content. The 25% fill is gone.

## 2. Two new sandboxed pane kinds

### `.claudeChat` and `.chatgptChat`

- New cases in `PaneSlotKind` with `isChatKind` discriminator.
- Each pane runs its own **non-headless** Chromium inside the cuabot
  container. (Headless triggers Cloudflare Turnstile on claude.ai —
  verified live; non-headless passes through to the login page cleanly.)
- Each Chromium runs with its own `--user-data-dir`:
  - `/home/user/.config/chromium-claude` for claudeChat
  - `/home/user/.config/chromium-chatgpt` for chatgptChat
- Each runs on its own CDP port: 9223 (claudeChat), 9224 (chatgptChat).
  The Browser pane stays at 9222.
- Each Chromium is positioned off-screen at `(4000, 4000)` so it doesn't
  visually overlap the Browser pane's foreground Chromium on `:100`.
  CDP `Page.captureScreenshot` works regardless of window visibility.

### Rendering pipeline

- `ChatPaneSandbox` polls `Page.captureScreenshot` at ~2 fps via the
  cuabot `/bash` endpoint with an inline Python helper that uses
  `websockets` to talk CDP.
- Image renders via `ChatScreenView` (an `NSViewRepresentable` wrapping
  `ChatScreenNSView`, a custom `NSView` that paints the JPEG aspect-fit
  and forwards mouse / keyboard).
- Mouse + keyboard input forwarded via CDP `Input.dispatchMouseEvent` /
  `dispatchKeyEvent` (a clean Swift wrapper in `Services/CDPInput.swift`,
  one Python invocation per event over cuabot `/bash`).

## 3. ChatBridge — bidirectional routing

### Trigger detection

`ChatTriggerParser` (case-sensitive, message-start only):
- `Code: <payload>` → route to Claude Code, start thread
- `Codex: <payload>` → route to Codex, start thread
- `Exit:` → end thread for current conversation
- Else (in active thread): continuation, route payload to the same target
- Else (no active thread): ignored

### Per-conversation thread state

`ChatBridge` keys threads by conversation ID extracted from the URL:
- `claude.ai/chat/<uuid>` → conversation ID = `<uuid>`
- `chatgpt.com/c/<uuid>` → conversation ID = `<uuid>`

Switching to a different conversation resets the thread. Per Nick's
ratification, `Exit:` clears thread state for that conversation only;
other conversations' state is preserved.

### Agent invocation with continuity

Per Nick's push-back, we use **session-id continuity**, not one-shot.

- **Claude Code:**
  ```
  echo "<payload>" | claude --print --output-format json \
      --dangerously-skip-permissions [--resume <session-id>]
  ```
  First turn: capture `session_id` from the JSON response. Subsequent
  turns: pass `--resume <session_id>` for the same chat conversation.
  **Continuity preserved across routed turns** within one chat conversation.
- **Codex:**
  ```
  echo "<payload>" | codex exec --json [...]
  echo "<payload>" | codex exec resume <session-id> --json [...]
  ```
  Codex's `--json` is best-effort here — its event stream schema is less
  stable than claude's; we use the last non-empty JSON object's
  `message`/`result`/`text` field. **Documented v1.5 weak point:** if
  Codex's --json output format shifts, response extraction may need to
  re-tune. Diagnostics surfaces low-quality / empty responses.

### Posting back into the chat (per Nick: textarea-only, no auto-submit)

- `ChatPostbackJS.setTextareaClaude(text)` and `setTextareaChatGPT(text)`
  inject a CDP `Runtime.evaluate` that:
  - Finds the chat input element (selectors documented below)
  - Uses `document.execCommand('insertText', false, …)` for the React-
    controlled contenteditable in claude.ai's case
  - Uses the React-aware native setter on `HTMLTextAreaElement` for
    chatgpt.com's `<textarea>`
- **Does NOT submit.** User reviews + presses Send.
- Falls back via multiple selectors so a single DOM change doesn't
  immediately break everything.

### DOM selectors (will change — Diagnostics surfaces breaks)

**claude.ai** (verified DOM as of 2026-05-13):
- User message: `[data-testid="user-message"]`
- Input: `[data-testid="chat-input"] [contenteditable="true"]` (fallback:
  `[contenteditable="true"][role="textbox"]`)

**chatgpt.com** (verified DOM as of 2026-05-13):
- User message: `[data-message-author-role="user"]`
- Input: `#prompt-textarea` (fallback: `textarea[name="prompt"]`)

When ChatBridge's selector lookup returns null,
`DiagnosticsLog.shared.log(.selectorMissing, …)` records the event so
the user notices the breakage.

### Visual badge — `→ Claude Code` chip

`RoutingBadge` appears in the chat pane header when ChatBridge has an
active routing thread for the pane's current conversation. Chip color
matches the routed target's accent (Claude Code purple, Codex green).

## 4. Diagnostics tab

New Settings tab `Diagnostics` shows the last 500 ChatBridge events:
- `trigger` (yellow) — Code:/Codex:/Exit: detected
- `route` (purple) — message dispatched to agent
- `response` (green) — agent response captured
- `postback` (green) — textarea set in chat pane
- `selector` (red) — DOM selector failed to match
- `error` (red) — any other failure
- `info` (gray) — registration / lifecycle

Cleared on app restart; in-memory only.

## Known fragilities / v1.6 punch list

- **DOM selectors will break.** When claude.ai or chatgpt.com redesigns,
  the existing selectors in `ChatPostbackJS` will need updates.
  Diagnostics surfaces this loudly via `selectorMissing` log entries.
- **Codex --json response parsing** is heuristic. The agent's last
  message is extracted via best-effort field probing; if Codex changes
  its event stream schema we may need to re-tune.
- **Headless chromium triggers Cloudflare on claude.ai.** v1.5 uses
  non-headless off-screen chromium. If chromium ever surfaces or gains
  focus, the user may briefly see the off-screen chromium flash. Hasn't
  happened in testing but worth flagging.
- **Off-screen chromium at (4000,4000)** assumes the X display is at
  least 2560×1440. If the user manually changes display size, the chat
  chromiums may become partially visible. v1.6 could move them further
  off (-9999, -9999) and let WM clip.
- **Chat polling cadence is fixed at 3 s.** Faster polling would feel
  more responsive but stresses cuabot /bash. Adaptive cadence (1 s
  active routing, 5 s idle) is a v1.6 task.
- **Auto-trust prompts** — claude --print sometimes asks for trust on
  a folder. With `--dangerously-skip-permissions`, this should be
  bypassed, but if claude evolves this flag's behavior the routing
  could stall. Surface via Diagnostics if response time exceeds 60s.
- **`Exit:` doesn't visually confirm.** It clears thread state and
  removes the routing badge, but the chat user only sees the badge
  vanish — no toast. v1.6 could log to Diagnostics + show a transient
  notification.
