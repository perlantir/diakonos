# Diakonos v1.1 — Architecture pivot

**Date:** 2026-05-13
**Branch:** `phase/1-v1.1` (cut from `phase/0-v1-build`)
**Status:** Implemented (not yet merged to main)

## Why v1.1 exists

v1 ran every pane inside a single cua Docker container via `docker exec -it`.
The Terminal pane gave you a shell in an aarch64 Linux container, not on your
Mac. The Claude Code pane ran `claude` inside that same container, with no
access to the host's filesystem or PATH. That was wrong: the use case is a
**native macOS dev workspace** with AI panes operating on the user's real
machine, plus a **sandboxed browser** for visiting untrusted web content.

v1.1 keeps everything good about v1 (the visual shell, design tokens, prefs
window, app icon, the cua HTTP integration knowledge) and re-aims the panes:

| Position    | v1                                    | v1.1                                            |
|-------------|---------------------------------------|-------------------------------------------------|
| Top-left    | bash in container (docker exec)       | **Native shell** (`$SHELL -l` in `$HOME`)       |
| Top-right   | `claude` in container                 | **Native** `claude --dangerously-skip-permissions` with project-folder picker |
| Bottom-left | bash in container (themed orange)     | **Native shell** "Terminal 2" (no theming)      |
| Bottom-right| WKWebView (host-side)                 | **Sandboxed Chromium** via cuabot Xpra HTML5    |

## Decisions superseded

### D4 — "cua via subprocess, not as a library"

**v1.1 scope contraction:** D4 was the design backbone for the entire v1 product.
v1.1 narrows D4 to apply to the **Browser pane only**. The Terminal, Claude
Code, and Terminal 2 panes are pure native — they don't touch cua at all.
D4 remains the correct call for the Browser pane (cua's Python SDK is still
the right way to drive sandboxed Chromium; we still talk to cuabot via
subprocess + HTTP).

See `docs/decisions.md` for the annotated D4 entry.

- XcodeGen from `project.yml` (D8).

## What changes

### Surfaces removed

- **Toolbar status indicator.** v1's `StatusIndicator` showed global cua-sandbox
  health. v1.1 doesn't have a global sandbox state — only the Browser pane has
  a sandbox, and its state surfaces as a dot on its own URL bar.
- **Manual / Autonomous toggle.** Was decoration; deleted.
- **Sandbox section in Preferences** (General / Sandbox / Panes / Agent /
  Shortcuts / About → General / Panes / Agent / Shortcuts / About).
- **Hermes API key field** (no Hermes pane any more).

### Services removed / pared down

- `CUASandboxManager` — **deleted.** Replaced by Browser-pane-local
  `BrowserSandbox` that owns cua lifecycle only when the Browser pane needs it.
- `CUAProcessSupervisor` — **deleted.** Inlined `Process` handling into
  `BrowserSandbox`.
- `AgentMode` — **deleted** (no more toolbar toggle).
- `SandboxedPaneBody` — **deleted** (was a global gate; no longer needed
  since 3/4 panes are unconditional native).
- `HermesAgentPaneView` — **deleted** (pane replaced by generic Terminal 2).
- `KeychainStore.Key.hermes` — **dropped.**

### Surfaces rewritten

- `TerminalPaneView` — now native: spawns `$SHELL` in `$HOME` via SwiftTerm.
  Generic; used by both Terminal and Terminal 2 panes.
- `ClaudeCodePaneView` — native; spawns
  `$SHELL -l -c "cd <folder> && exec claude --dangerously-skip-permissions"`.
  Folder pickable from header chip, persisted in UserDefaults
  (`claudeCodeFolderPath`), defaults to `$HOME`. Folder change = kill + respawn.
- `BrowserPaneView` — sandboxed Chromium via cuabot Xpra. URL bar drives
  Chromium-in-sandbox via `POST /bash`. Back/Forward/Reload via `xdotool` key
  injection.

## Bugs fixed along the way

1. **Settings (Cmd+, / gear) crash.** `SandboxSection` declared
   `@EnvironmentObject CUASandboxManager` that the Settings scene never injected.
   Removed `SandboxSection` entirely.
2. **Terminal keystroke bleed.** `TerminalPaneView.updateNSView` never assigned
   `lastSpawnKey` after spawn, so every SwiftUI rerender forced terminate +
   respawn on all three terminal panes. Fixed; also dropped the redundant outer
   `NSView` wrapper so SwiftTerm's own `acceptsFirstResponder` cleanly isolates
   focus per pane.

## Browser pane: approach ladder evaluated

- **A — Xpra HTML5 in WKWebView.** ✓ **Picked and working.** cuabot's container
  exposes Xpra on `:10000`; WKWebView loads it directly. Verified via TCP
  connection from `com.apple.WebKit.Networking` XPC to `[::1]:10000` during a
  live Diakonos run.
- B — floating Mac window via `cuabot chromium`. Not needed; A worked.
- C — VNC. Not needed; A worked.
- D — WKWebView host-browser fallback. Not needed; A worked.

## Known v1.1 limitations / v1.2 punch list

- Xpra HTML5 client likely needs one "Connect" click on first load. v1.2:
  try `?submit=true&action=connect` autoconnect URL params.
- Each URL-bar navigation spawns a fresh Chromium command; on `--no-sandbox`
  Chromium may not always fold into the existing window. v1.2: use CDP via
  `--remote-debugging-port`.
- Back/Forward/Reload rely on `xdotool` being present in the cuabot image.
  Silently no-op if missing.
- No CDP-based "current URL" feedback from the sandboxed Chromium back into
  Diakonos's URL bar yet. The bar reflects what the user typed, not what
  Chromium is showing after follow-on link clicks.
