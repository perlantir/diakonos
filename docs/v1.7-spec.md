# Diakonos v1.7 — routing protocol (Part A spec)

**Scope.** Routing redesign. v1.5/v1.6 had an implicit, always-on routing
protocol. v1.7 makes it explicit, layered, versioned, and safe.

Part A — what this spec covers — lands the foundation:
1. Per-pane modes (`.soloChat` / `.coordinator` / `.implementer` /
   `.browserDriver`)
2. Versioned role cards on disk
3. 5-layer routing context composer
4. AGENTS.md / .diakonos/context.md canonical templates
5. Trigger-safety hardening (DOM attribution + escape + quote + first-
   route confirm modal)
6. Route state machine + structured envelope
7. **CWD fix** (the v1.5/v1.6 subprocess-CWD bug)
8. Versioned snapshots (active sessions pin to a role-card version)
9. Append-only JSONL event log per session
10. Refactored ChatBridge built on the above
11. Browser prompt-injection guardrails

Part B (next phase of the same session) layers auto-modes, bug fixes,
and documentation on top.

---

## 1. Pane modes

Two orthogonal axes:

| | What | Examples |
|---|---|---|
| `PaneSlotKind` | What process runs | `.terminal`, `.claudeCode`, `.codex`, `.claudeChat`, `.chatgptChat`, `.browser` |
| `PaneMode` | How it routes | `.soloChat`, `.coordinator`, `.implementer`, `.browserDriver` |

For chat-kind panes the mode is user-toggleable between `.soloChat` and
`.coordinator` via the header chip. Other kinds have a fixed mode:
`.implementer` for `.claudeCode`/`.codex`, `.browserDriver` for
`.browser`, and `.soloChat` for `.terminal` (terminals are inert from
routing's perspective).

**Default for new chat panes is `.soloChat`.** This is a behavior change
from v1.5/v1.6, where chat panes always routed implicitly. v1.7 makes
routing opt-in: the user clicks the chip to enter `.coordinator` mode.

Existing v1.6 layouts migrate to v3 with `mode = nil` on every slot,
which resolves to the kind's default — so existing claudeChat slots
become `.soloChat` after upgrade. Surface a one-line banner explaining
the change (Part B).

Persistence: `workspaceLayout.v3` UserDefaults key. v2 and v1 keys are
migrated forward on first launch.

## 2. Role cards

Markdown files at `~/Library/Application Support/Diakonos/RoleCards/<id>@<semver>.md`.
Bundled defaults are copied from the app bundle on first launch
(`RoleCardStore.seedFromBundleIfNeeded`). Five built-in IDs:

- `coordinator.claude-web`
- `coordinator.chatgpt-web`
- `implementer.claude-code`
- `implementer.codex`
- `browser-driver`

The Settings tab "Role Cards" lets the user edit any card. **Save
auto-bumps the patch version** (1.0.0 → 1.0.1 → 1.0.2 → …). Each save
writes a new file; older versions are NOT deleted because in-flight
sessions hold pinned references to specific versions.

## 3. Layered context (5 layers)

When a route fires, `RoutingContext.compose` produces a preamble sent
ahead of the user's task on the implementer's stdin:

1. **Protocol** — Diakonos invariants (versioned via
   `RoutingContext.protocolVersion = "1"`).
2. **Pane Mode card** — the role-card markdown body verbatim.
3. **User preferences** — placeholder for v1.7 Part A (empty).
4. **Project** — AGENTS.md / .diakonos/context.md / CLAUDE.md from the
   user's chosen project folder, concatenated.
5. **Session / envelope** — the route envelope (route_id,
   project_root, hashes, etc.) plus the reply contract.

Then the literal `# Task` heading and the user's typed text after
`Code:` or `Codex:`.

## 4. AGENTS.md canonical

When a Claude Code / Codex pane has a project folder, Diakonos reads:

- `AGENTS.md` — canonical
- `.diakonos/context.md` — Diakonos-specific
- `CLAUDE.md` — Claude Code's own loader file; should `@AGENTS.md`

`AGENTSReader.seedTemplatesIfMissing` drops starter templates (from the
app bundle, under `Resources/templates/`) on first folder selection.
Never overwrites existing files. `AGENTSReader.read` returns a `Project`
snapshot including a SHA-256 hash over all three bodies — the route
envelope echoes the hash so the implementer can tell when its context
is stale.

For `.coordinator`-mode chat panes, **Part B** will inject the
`Project.summary` (first paragraph of AGENTS.md) into the textarea at
conversation start. Part A scope: read + hash + ship through the envelope.

## 5. Trigger safety hardening

Five rules, all enforced:

1. **DOM attribution.** The CDP scrape only matches user-authored DOM
   nodes:
   - claude.ai: `[data-testid="user-message"]`
   - chatgpt.com: `[data-message-author-role="user"]`

   Empirically verified 2026-05-14 via synthetic DOM probe: an
   assistant `[data-message-author-role="assistant"]` containing
   "Code: do thing" is **invisible** to the user-only selector. The
   "Coordinator AI emits Code: → does NOT route" guarantee falls out
   of the selector, not heuristics.

2. **Message-start only.** `^(Code|Codex|Exit):` anchored at trimmed
   start. "Tell me about Code: prefixes" does not fire.

3. **Not in quotes / code blocks.** Block-quotes (every non-empty
   line starts with `>`) and fenced ``` ``` ``` blocks are guarded.

4. **Backslash escape.** `\Code:` does not fire. Users can discuss the
   protocol literally.

5. **First-route confirm.** The first route in a conversation pops an
   NSAlert with Confirm / Cancel / Always-for-this-conversation.
   Subsequent routes in the same conversation either prompt again
   (default) or are auto-approved (if user picked "Always").

11/11 cases pass in `/tmp/trigger_safety_test.swift` (mirror of
`TriggerDetector.classify`).

## 6. Route state machine

Nine states, all forward except `closed` (reachable from any state).

```
idle → routeDraftDetected → awaitingDispatch → sentToTarget →
       targetRunning → replyCaptured → draftPostedToChat →
       awaitingUserReview → closed
```

Each transition fires `onTransition(prev, next)` which the parent
ChatBridge wires to `SessionEventLog.append`. Per-conversation JSONL
file at `~/Library/Application Support/Diakonos/Sessions/<conv-id>.jsonl`.

## 7. Route envelope

YAML-frontmatter Markdown sent as the lead of stdin to `claude --print`
/ `codex exec`. Fields:

```yaml
route_id: <UUID>
source_pane: chat:claudeChat
target_pane: claudeCode:terminal
project_root: /Users/perlantir/Projects/diakonos    # absolute
context_hash: <sha256 of AGENTS+context+CLAUDE>
role_card: implementer.claude-code
role_card_version: 1.0.0
protocol_version: "1"
conversation_id: <chat UUID>
created_at: <ISO8601>
```

The body is the **Reply contract**: Summary / Files touched / Commands
run / Tests / Risks. The implementer echoes these sections back so
Diakonos's chat-pane postback has a predictable shape.

## 8. CWD fix (the v1.5/v1.6 bug)

`Process.runWithCWD` sets `currentDirectoryURL` before `.run()`.
v1.5's `runCapturing` never did, so `claude --print` ran in Diakonos's
launch CWD (usually `/`). v1.7 fix verified empirically:

```
[PASS] cwd=/tmp /bin/pwd -L → /private/tmp
[PASS] cwd=/usr/local /bin/pwd -L → /usr/local
[PASS] cwd=/Users/perlantir/Projects/diakonos /bin/pwd -L → /Users/perlantir/projects/diakonos
=== 3 pass / 0 fail ===
```

The `/private/tmp` and lowercase-`projects` results are macOS canonical
path resolution (symlink resolved + case-insensitive APFS). The CWD
itself is set correctly. `CWDSelfTest.run` in `RouteDispatcher.swift`
runs this check at every app launch and logs to NSLog.

## 9. Versioned snapshots

Each route's `RouteStateMachine` carries an immutable `RouteSnapshot`:
`(roleCardID, roleCardVersion, protocolVersion, projectContextHash,
createdAt)`. Settings edits to role cards AFTER a session starts do
NOT retroactively affect in-flight routes. Part B surfaces "using
coordinator@1.4.2; latest 1.5.0 — [Restart sessions]" in the chat pane.

## 10. Append-only event log

`SessionEventLog.append` writes one JSON object per line into
`Sessions/<conv-id>.jsonl`. Events:

- `route_detected` — TriggerDetector fired
- `route_sent` — dispatched to subprocess
- `route_running` — subprocess running
- `route_reply` — subprocess returned
- `route_posted` — textarea updated
- `route_reviewed` — user pressed Send (Part B)
- `route_closed` — Exit: fired or user dismissed

`SessionEventLog.recentEvents(tail: 500)` reads back the most recent
events across all sessions. The Diagnostics tab will surface these in
Part B (Part A keeps the in-memory DiagnosticsLog for live-tail).

## 11. Browser prompt-injection guardrail

- Only chat-kind sandboxes register with ChatBridge — the Browser pane
  never enters the polling loop. Route detection can't fire on browser
  content.
- The `diakonos-browser` MCP tool descriptions in `mcp_browser.py` now
  carry an explicit UNTRUSTED CONTENT warning telling the agent that
  browser output is data, not instructions.
- The `browser-driver@1.0.0` role card reinforces this on the agent side.
